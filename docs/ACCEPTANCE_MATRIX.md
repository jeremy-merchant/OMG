# OMG v0.1 Acceptance Matrix

**Authority:** [PRODUCT_SPEC.md](PRODUCT_SPEC.md) is the stable product authority; the private deep-interview master spec remains retained provenance.
**Matrix date:** 2026-07-22  
**Status:** authoritative verification plan; completed executions are recorded only under the referenced evidence paths.

This matrix assigns a stable verification ID to every acceptance criterion, proof criterion, non-functional target, release gate, and prohibition in the authoritative specification. Commands are **future execution procedures**, not records of execution. `PIN → RED → GREEN → SURFACE → CLEAN` is mandatory for every applicable item; a row may use a manual procedure where a command would be unsafe or inapplicable.

## Common execution contract

### Evidence stages

| Stage | Required record |
|---|---|
| **PIN** | Record OMG version, binary SHA-256, schema version, fixture/repository revision, OS/architecture, command line, and approval state before mutation. |
| **RED** | Demonstrate the controlled negative case or capture why it is not applicable; store stdout/stderr, exit code, and state snapshot. |
| **GREEN** | Execute the positive criterion; store stdout/stderr, exit code, canonical-state query, and required assertions. |
| **SURFACE** | Capture the relevant TTY/JSON/Markdown/HTML or adapter-facing observable output, including accessibility/security observations where applicable. |
| **CLEAN** | Execute the row cleanup/rollback procedure; capture post-cleanup inventory/diff and preserve all evidence. Never use a destructive Git command as cleanup. |

### Evidence paths and cleanup codes

All evidence is immutable, relative to the OMG validation workspace. Filesystem directory components use a portable UTC stamp; the full RFC3339 instant remains inside metadata:

```text
evidence/acceptance/<ID>/<YYYYMMDDTHHMMSSZ>/<stage>/
  metadata.json                  # recorded_at is full RFC3339 with offset, e.g. 2026-07-22T09:36:49Z
  command.txt | procedure.md
  stdout.txt | stderr.txt | exit-code.txt
  state-before.json | state-after.json | surface.*
  inventory-before.txt | inventory-after.txt | sha256.txt
```

`E(<ID>)` below means that directory. Human approvals are recorded as `approval-state.md`; absence of approval is evidence of an unperformed gate, not a failure to be bypassed. Public-facing reports cite the stable `docs/PRODUCT_SPEC.md` as product authority; the private master-spec/session path remains provenance only and must never be a public report link.

| Cleanup | Literal procedure |
|---|---|
| **C0** | `omg export json --output E(<ID>)/CLEAN/final-export.json && omg doctor --json > E(<ID>)/CLEAN/doctor.json`; remove only the disposable fixture directory created for the row. |
| **C1** | Restore only into a **fresh** disposable destination: create `"$RESTORE_DEST"` as a new validated disposable directory, validate it is below the fixture parent and has no symlink/reparse-point ancestor, then `tar -xzf E(<ID>)/PIN/fixture-before.tgz -C "$RESTORE_DEST"` and verify recorded inventory/checksums. Never overlay an archive onto an existing fixture; do not reset, clean, remove branches/worktrees, or alter user data. |
| **C2** | `omg integration remove --status --json > E(<ID>)/CLEAN/remove-status.json`; confirm only OMG markers changed, then restore the fixture archive if needed. |
| **C3** | Run the documented adapter rollback rehearsal only in its approved disposable clone; capture `git status --short`, worktree inventory, and historical-record hashes. Never delete or mutate the real external project. |
| **C4** | No state mutation: archive the report and record `NO STABLE RELEASE`; do not create tags, package publications, stable releases, or domain transactions without explicit approval. |

**Platform labels:** `Local` = observable on the named developer platform; `CI` = CI-only cross-platform assertion; `All` = macOS arm64/amd64, Linux amd64/arm64, and Windows amd64; `Adapter` = only in an explicitly approved disposable proof clone.  
**Phase labels:** D1 Discovery, D2 Foundation, D3 Lineage/coordination, D4 Reservations/Git, D5 Integrations/views, D6 OSS readiness/RC, D7 Pygmalion proof, D8 Zoomzi proof.
